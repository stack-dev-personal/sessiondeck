## User's words (verbatim)
- "Make it so that working vs. idle state is decided based on a longer timeframe so that the sessions don't flip around in order so much."
- "Clicking on a session should produce a popout instead of a sidebar. Within this popout the subagents should be displayed in a slightly smaller version of the overarching board (acting almost like an expanding bill of materials rollup). This should continue until the lowest level nested agent is displayed."
- "Instead of the 5hr and 7d (we should add fable usage specifically as well) being displayed within each sessions div, it should instead be displayed as a square widget with the usage indicators. This widget should be moveable/manipulatable by the mouse so the user can place it where it is most convenient (this will eventually be a popout when this becomes a dedicated desktop application)."

## Requirements
- R3.10 Stable working/idle display. Keep the contract state machine as is (Stop still means idle; decision 9 stands). Add a display-level activity with hysteresis: a session shows and sorts as working until it has been continuously idle or waiting for a grace period, default 120 s, configurable in Settings (range 0 to 15 min). Waiting for input (permission, question) still surfaces immediately: it needs the user. Board order is stable: a card moves group at most once per grace period, and within a group order does not change on every delta (sort key stable, e.g. last-entered-group time). Tests: a session with Stop then UserPromptSubmit 30 s later never leaves the working group; one idle for 121 s moves once.
- R3.11 Session popout replaces the side drawer. Clicking a card opens a large centered popout (dialog semantics, focus trap, Esc and click-outside close, deep-linkable with a plain #session-<id> hash if the router allows). Inside: the session header (state, model, effort, cost, branch) and its subagents rendered as a smaller version of the board (same card component at a compact size). Each subagent card that has its own subagents expands in place into the next level, recursively, like a bill-of-materials rollup, down to the deepest agent; expand/collapse per node and "expand all". Nesting comes from the data: parent links from hook envelopes (agent_id) and, when S7 lands, transcript subagent attachment. Where a parent link is unknown, the agent shows at the session's first level with an "unlinked" marker, and the gap is recorded in the session log. S8 (content view) renders inside this popout afterwards; leave a content slot.
- R3.12 Usage widget. Remove the 5h and 7d meters from every session card. Add one square widget showing account usage: 5-hour and 7-day used percentage with reset times (from statusLine rate_limits, freshest payload across sessions; they are account-wide), plus a Fable 7-day row. Claude Code's statusLine sends only five_hour and seven_day today (checked 2026-10-28 on 10,027 live payloads), so the Fable row is an estimate: Fable 5.1 spend and tokens over the last 7 days from hub cost history, labelled "estimate". If a payload ever carries a Fable-specific window (any seven_day_* key naming fable), use it instead and drop the label. The widget is draggable with the mouse (pointer events, keyboard-movable too), position kept per browser (localStorage, wrapped in try/catch), snaps inside the viewport on resize, and can collapse to a small chip. Build it as a self-contained component with its own data hook so S15 (Electron) can host it in its own window later.
- R3.13 Mock mode covers all three (popout with three nesting levels, widget with and without the Fable window, a session flapping Stop/prompt).
