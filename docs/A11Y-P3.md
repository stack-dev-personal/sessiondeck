# Accessibility checklist, Phase 3 live board (S6, unit U5)

**This is a substitute.** The `design:accessibility-review` skill was not available in the sprint container. This is a WCAG 2.1 AA checklist run by automated checks (axe with tags wcag2a, wcag2aa, wcag21a, wcag21aa; computed contrast; Playwright steps) plus manual reasoning. **The user must run `design:accessibility-review` once on the laptop** and compare. No screen reader (NVDA, VoiceOver) was run here; live-region rows are verified structurally only.

Surfaces: ConnectionBanner (closed, invalid, connecting, open), Header connection status, BoardToolbar (host and project filters, "Showing n of m", "N hidden need attention"), attention accent and arrival glow, Settings (notifications, per-state tones, mute, insecure-URL warning, Saved), ErrorBoundary fallback. Both themes unless stated.

Evidence: `packages/web/e2e/R3.7-live.spec.ts` (new), `packages/web/e2e/a11y-helpers.ts` (new), `packages/web/e2e/R3.7.spec.ts` (existing), `pnpm -F @sessiondeck/web contrast`. Screenshots in `/state/1/screens/S6/`: `R3.7-live-dark.png`, `R3.7-live-light.png`, `R3.7-banner.png`, `R3.7-banner-light.png`, `R3.7-320.png`, `R3.7-settings-{dark,light}.png`, `R3.7-motion.json`. Fix commits: `cfbf31b` (reflow, live region, header glyph), `615631a` (control boundaries, baselines). Test commit: `0d89322`.

## Design-system change needed (owner of 03-design-system.md)

Add `--border-control` to the tokens: dark `#6f7c8b`, light `#77818b`. Purpose: border of interactive controls (selects, inputs, buttons), WCAG 1.4.11 needs 3:1 against bg and surface-1..3; `--border` (1.26 to 1.50:1) stays for cards, gutters and dividers. Implemented in `src/styles/tokens.css`; `03-design-system.md` was not edited (outside this unit's paths).

Add "compact form wraps at or below 40rem (min 36 px)" to section 5.1 of `03-design-system.md`: the compact row is one 36 px row above 40rem (640 px); at or below it the fixed-width items (state 9rem, meters 3.5rem each, agents 5rem, tasks 4rem, name takes the rest) wrap onto extra lines, so card height is `auto` with a 36 px minimum, stable per viewport (WCAG 1.4.10 reflow at 320 px). Every item has a fixed width so null to value moves nothing; `e2e/R3.2.spec.ts` sweeps 320, 360, 400, 440, 480, 520, 560, 600, 640, 800 and 1280 px with 12 active subagents, asserting every slot's right edge stays inside the card content box and the name width is above 0.

Visual baselines do not cover border colour (Playwright default per-pixel threshold 0.2); `measureControlBorders` (e2e) and `tokens.contrast.test.ts` do.
